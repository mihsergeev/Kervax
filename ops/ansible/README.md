# Массовое обновление helper'ов Kervax

`kervax_helpers.yml` переустанавливает setup-скрипты (helper'ы) на нодах.

## Почему это плейбук, а не кнопка в панели

Helper ставится от root. Если бы панель умела запускать его сама, её взлом означал бы
root на всём парке — а вся схема Kervax построена на обратном: агент непривилегирован,
привилегированные операции идут через узкий белый список, панель секретов не хранит.

Поэтому панель только **показывает**, где helper устарел, и отдаёт список хостов.
Выкатывает человек. Скрипты плейбук берёт **локально из репозитория** — с панели ничего
не скачивается, так что даже скомпрометированная панель не может подсунуть свой код.

## Как пользоваться

Панель: Главная → «Требует действий» → «🧩 обновить сразу на N нодах» — там готовая
команда со списком хостов.

```sh
# сухой прогон: покажет, что и где обновится, ничего не меняя
ansible-playbook playbooks/kervax_helpers.yml -l 'web-01,db-01' --check --diff

# боевой
ansible-playbook playbooks/kervax_helpers.yml -l 'web-01,db-01'
```

Плейбук идемпотентен: ставит недостающее, обновляет то, где версия разошлась, и не
делает ничего на повторном прогоне.

## Как плейбук решает, что кому ставить

Ни одного helper'а по имени плейбук не знает — он читает `agent/*.sh` и спрашивает у
самих скриптов. Каждый обязан ответить одним из трёх способов:

| В скрипте | Что означает | Примеры |
|---|---|---|
| `KERVAX_SETUP_ALWAYS=1` | безопасен на любой ноде — ставим всюду | `timesync-setup`, `agent-watchdog`, `dbstat-setup` |
| `KERVAX_SETUP_WHEN="…"` | shell-условие, которое проверяется **на ноде**: истинно — ставим | `kubeexpiry-setup` (только где есть кластер), `backupserver-setup` (только на бэкап-сервере) |
| ни того, ни другого | ставится только вручную; плейбук лишь обновляет там, где уже стоит | `kube-setup` — он выдаёт панели доступ в кластер, это решение человека |

Условие — обычная строка для `sh`, без одинарных кавычек внутри:

```sh
KERVAX_SETUP_VERSION=0.1
KERVAX_SETUP_WHEN="command -v k0s >/dev/null 2>&1 || [ -d /var/lib/k0s/pki ]"
```

Благодаря этому **новый helper разъезжается по нужным нодам сам** — плейбук править не
надо. Раньше без `ALWAYS` скрипт не приезжал никуда: прогон по парку отрабатывал
вхолостую (`changed=0`), а панель продолжала требовать действий. Забыть про это нельзя:
`ops/selfcheck.py` не пропустит helper, который не сказал, каким нодам он нужен.

Прогон печатает, что не подошло:

```
TASK [Ставить нечего]
ok: [web-01] => "Всё на месте. Не подошли по условию: kubeexpiry-setup"
```

## Где лежат скрипты

Каталог ищется автоматически: `files/kervax/` рядом с плейбуком (репозиторий ansible)
либо `agent/` (репозиторий панели). Если репозиторий панели лежит в стороне —
`-e kervax_repo=/путь/к/репозиторию` (или `-e kervax_src=/путь/к/agent`); удобнее
задать это один раз в `group_vars`, чем писать при каждом прогоне.

Единственный источник правды — `agent/` в репозитории панели: панель флагует
устаревшие helper'ы по тем самым версиям. Копия в `files/kervax/` — фолбэк, и если
вы ей пользуетесь, обновляйте её вместе с панелью:

```sh
cp <репозиторий-панели>/agent/*-setup.sh <репозиторий-ansible>/files/kervax/
```
