# Установка Kervax

[English version](install.md) · [README](../README.ru.md) · [Зачем это](why.ru.md)

За десять минут на чистом сервере получается панель по https с настоящим
сертификатом, без своего домена и без единой строчки в конфигах nginx.

---

## Что понадобится

- Сервер с Linux и Docker-совместимым ядром. Хватает **2 ГБ памяти** — проверено
  на Ubuntu 26.04 с 2 ГБ: панель собирается из исходников и работает.
- **Свободные порты 80 и 443.** Их займёт Caddy, который сам получит сертификат
  Let's Encrypt. Если на сервере уже есть nginx или другой веб-сервер — см.
  [«Уже есть свой прокси»](#уже-есть-свой-прокси).
- Доступ root (или sudo).
- Домен — **не обязателен**: по умолчанию используется `<IP-сервера>.sslip.io`.

> **Что такое sslip.io.** Это публичный DNS, который отвечает тем адресом,
> который записан в самом имени: `95.216.199.167.sslip.io` резолвится в
> `95.216.199.167`. Ничего регистрировать и настраивать не нужно, а Let's Encrypt
> выдаёт на такое имя обычный сертификат. Для постоянной установки лучше свой
> домен, но чтобы посмотреть панель — этого достаточно.

---

## Быстрый путь: одна команда

```bash
curl -fsSL https://raw.githubusercontent.com/mihsergeev/Kervax/main/ops/quickstart.sh | sudo sh
```

Скрипт напечатает адрес панели и пароль администратора. Больше ничего вводить не
нужно.

Со своим доменом (заранее направьте на сервер A-запись):

```bash
curl -fsSL https://raw.githubusercontent.com/mihsergeev/Kervax/main/ops/quickstart.sh | sudo sh -s -- --domain kervax.example.com
```

Сразу с ограничением доступа по IP — рекомендуется, если панель смотрит в
интернет:

```bash
curl -fsSL https://raw.githubusercontent.com/mihsergeev/Kervax/main/ops/quickstart.sh | sudo sh -s -- --allow-ips "203.0.113.10 198.51.100.23"
```

### Что скрипт делает

Никакой магии, всё то же самое можно сделать руками (см. следующий раздел):

1. ставит Docker, если его нет;
2. проверяет, что порты 80 и 443 свободны, — иначе сертификат не выпустится, и
   лучше узнать об этом сразу;
3. поднимает `caddy-docker-proxy` — он выдаёт TLS и раздаёт трафик по
   меткам контейнеров;
4. клонирует репозиторий в `/opt/kervax`;
5. делает `.env` со случайными паролем администратора, JWT-секретом и паролем
   базы;
6. поднимает панель из готовых образов (`--build` — собрать из исходников);
7. ждёт, пока `https://<домен>/api/health` ответит, и печатает доступы.

## Ручная установка

То же самое по шагам — если хочется контролировать каждый.

### 1. Docker

```bash
curl -fsSL https://get.docker.com | sudo sh
```

### 2. Caddy для TLS

Панель не занимается сертификатами: перед ней стоит обратный прокси. Готовый
вариант — `caddy-docker-proxy`: он читает метки контейнеров и сам получает
сертификаты.

```bash
sudo docker network create caddy
sudo mkdir -p /srv/caddy && cd /srv/caddy
```

Положите рядом `compose.yml`:

```yaml
services:
  caddy:
    image: lucaslorentz/caddy-docker-proxy:2.10-alpine
    restart: unless-stopped
    ports: ["80:80", "443:443"]
    environment:
      CADDY_INGRESS_NETWORKS: caddy
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - ./data:/data
    networks: [caddy]
networks:
  caddy:
    external: true
```

```bash
sudo docker compose up -d
```

### 3. Репозиторий и настройки

```bash
sudo git clone https://github.com/mihsergeev/Kervax.git /opt/kervax
cd /opt/kervax && sudo cp .env.example .env
```

Заполните в `.env` пять строк:

```ini
KERVAX_ADMIN_PASSWORD=<минимум 12 символов>
KERVAX_JWT_SECRET=<openssl rand -hex 32>
KERVAX_DB_PASSWORD=<любая длинная случайная строка>
KERVAX_DOMAIN=95.216.199.167.sslip.io
KERVAX_PANEL_URL=https://95.216.199.167.sslip.io
```

Первые три панель проверяет на старте и **отказывается запускаться** с пустыми
или дефолтными значениями. `KERVAX_PANEL_URL` — тот же домен со схемой: из него
собирается команда установки агента и ссылки в алертах.

Шестая строка — список адресов, которым разрешено открывать панель:

```ini
KERVAX_ALLOW_IPS=203.0.113.10 198.51.100.23
```

**Пустое значение означает «пускать всех»** — тогда единственная защита это
пароль и второй фактор. Эндпоинты агентов (`/api/agent/*`) в список не входят
никогда: агенты приходят с адресов наблюдаемых нод и авторизуются своими
токенами.

Свой адрес берите тот, каким вас видит **сам сервер**, а не тот, что показывает
сервис определения IP: у машины с несколькими каналами они отличаются, и панель
закроется в том числе от вас. Проще всего подсмотреть в уже открытой ssh-сессии:

```bash
ssh <сервер> 'echo $SSH_CLIENT' | awk '{print $1}'
```

### 4. Запуск

Из готовых образов — быстро, ничего не собирается:

```bash
sudo docker compose -f compose.yml -f compose.ghcr.yml -f compose.caddy.yml up -d
```

Или из исходников — дольше (несколько минут: собираются Go-агент под две
архитектуры и фронтенд), зато вы точно знаете, что запускаете:

```bash
sudo docker compose -f compose.yml -f compose.caddy.yml up -d --build
```

В scale-режиме (несколько воркеров и отдельный планировщик) файлов больше:

```bash
sudo docker compose -f compose.yml -f compose.scale.yml -f compose.ghcr.yml -f compose.ghcr-scale.yml up -d
```

Чтобы не писать `-f` каждый раз, положите в `.env`:

```ini
COMPOSE_FILE=compose.yml:compose.ghcr.yml:compose.caddy.yml
```

### 5. Проверка

```bash
curl https://95.216.199.167.sslip.io/api/health
```

Ответ `{"status":"ok","version":"1.1.0"}` означает, что живы и панель, и база, и
сертификат. Первый сертификат выпускается до минуты — если сразу не ответило,
подождите и повторите.

## Первый вход

Откройте адрес панели, войдите как `admin` с паролем из `.env`. Сразу после:

1. **Смените пароль** (меню ⚙ → «Сменить пароль») — это завершит все прочие
   сессии.
2. **Включите 2FA** там же. Панель управляет доступом к инфраструктуре, и один
   пароль для неё — мало.
3. Если оставляли `KERVAX_ALLOW_IPS` пустым — впишите свой адрес и примените:
   `sudo docker compose up -d frontend`.

## Первый сервер под наблюдением

Нажмите **«Добавить сервер»**, дайте имя — панель покажет одну команду. Выполните
её на наблюдаемой машине от root:

```bash
curl -fsSL https://<ваша-панель>/api/agent/install.sh | sh -s -- https://<ваша-панель> <токен>
```

Что произойдёт: скачается статический бинарь агента, заведётся systemd-юнит от
непривилегированного пользователя `kervax`, поставятся вспомогательные скрипты
(бэкапы, инвентарь СУБД, домены веб-серверов, синхронизация времени). Через
несколько секунд машина появится в панели со всеми метриками — настраивать
экспортёры и прописывать цели не нужно.

Агент ходит **только наружу**, по HTTPS, к панели. Он не открывает портов, не
выполняет команд оболочки, а панель хранит лишь SHA-256 его токена.

## Первый сайт

**«Добавить монитор»** — достаточно ввести адрес: `example.com` или
`https://example.com/health`. Схема определится сама, TLS-сертификат и срок
регистрации домена начнут отслеживаться автоматически, а история и аптайм
появятся с первой же проверки.

## Дальше

**Свой домен вместо sslip.io.** Направьте A-запись на сервер, поправьте
`KERVAX_DOMAIN` и `KERVAX_PANEL_URL` в `.env` и примените:
`sudo docker compose up -d frontend backend`. Caddy получит новый сертификат сам.

**Уже есть свой прокси.** Не подключайте оверлей `compose.caddy.yml` — тогда
панель публикуется на хосте (по умолчанию `127.0.0.1:8080`, меняется через
`KERVAX_BIND`), и вы проксируете её своим nginx/traefik. Внутри контейнера
фронтенд слушает **8080** — он работает без root.

**Алерты.** ⚙ → «Алерты»: Telegram-бот или webhook. Текст каждого типа алерта,
пороги и область (все ноды / группа / выбранные) редактируются в панели.

**Обновление.**

```bash
cd /opt/kervax && sudo git pull
sudo docker compose up -d --build   # или без --build на готовых образах
```

Миграции базы применяются сами при старте. Данные лежат в `./data` и обновление
их не трогает.

**Резервные копии.** ⚙ → «Бэкап» — экспорт конфигурации (мониторы, серверы,
настройки) и расписание автоматических копий. Историю метрик резервируйте вместе
с каталогом `data/`.

**Удаление.**

```bash
cd /opt/kervax && sudo docker compose down -v && cd / && sudo rm -rf /opt/kervax
```

## Если что-то пошло не так

| Симптом | Причина | Что делать |
| --- | --- | --- |
| `https://…` не отвечает, в логах Caddy ошибки ACME | порт 80 или 443 занят, либо домен не резолвится в этот сервер | `sudo ss -lntp \| grep -E ':80\|:443'`, `getent hosts <домен>` |
| Сертификат не выпускается на своём домене | A-запись ещё не разошлась | подождите обновления DNS, проверьте `dig +short <домен>` |
| Панель отвечает 200 на `/api/health`, но страница не открывается | ваш адрес не в `KERVAX_ALLOW_IPS` | впишите свой IP или очистите список |
| Контейнер `backend` перезапускается | слабый или пустой секрет в `.env` | `docker compose logs backend \| tail -20` — там прямо написано, какой |
| Сборка падает без внятной ошибки | не хватило памяти | ставьте из готовых образов (`compose.ghcr.yml`) |
| Агент установился, но ноды нет в панели | нода не достучалась до панели | на ноде: `systemctl status kervax-agent`, `journalctl -u kervax-agent -n 30` |
| В команде установки агента написано `https://ПАНЕЛЬ` | не задан `KERVAX_PANEL_URL` | впишите в `.env` и `docker compose up -d backend` |

Логи целиком:

```bash
cd /opt/kervax && sudo docker compose logs --tail=100 backend scheduler frontend
```
