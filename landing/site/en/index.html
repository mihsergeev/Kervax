Security

A security audit on every server

No separate scanner or security agent: the same nodes, the same panel, the same alerts.

external scanalert on new ports

What is open to the internet

  • External scan of every node, matched with what listens inside: process and container for each port.
  • Allowlists respected: a port open only to your own addresses is not reported as exposed.
  • Cloudflare-only: verifies that an origin answers nobody but Cloudflare.
  • A new port on the internet raises an alert. An intended one is marked once.
  • Kubernetes LoadBalancer services are scanned the same way.

SSH and access

  • SSH: password and root login, brute force in progress, fail2ban or sshguard protection, version banner.
  • Accounts and keys: who can log in, with which keys, who has sudo and NOPASSWD, weak keys, accounts nobody uses.
  • Changes: a new key, user or sudo rule, a password login from a new address - alert with a "this is us" button.
  • Timeline of 90 days: ports, containers, users, sudoers, cron jobs.

CISA KEVUbuntu OVALendoflife.date

Vulnerabilities and end-of-life versions

  • Packages are matched against the Canonical OVAL feed: critical and already exploited in the wild (CISA KEV) only.
  • The kernel is checked by its running version, not the installed one: you see who needs a reboot.
  • End-of-life versions: OS, PostgreSQL, MySQL, Redis, nginx, PHP, Node.js, Python and more, from an endoflife.date snapshot shipped with the panel.
  • OS updates: pending security updates, automatic updates turned off, a reboot that keeps being postponed.
  • Containers that are privileged or carry host keys or the Docker socket, ports published past the firewall.

Disks and hardware

Failures show up before they happen

Forecasts from history, not thresholds on the current value.

SMARTRAIDNVMe

Disk wear and health

  • SSD wear forecast: measured rate, the dates of 90% and 100% at the current write rate, alert 60 days ahead.
  • Who writes to disk: units, containers and pods, per hour, day and week.
  • Health: degraded RAID, SMART failures, growing reallocated and pending sectors, disks that disappeared, kernel I/O errors.
  • Disks of virtual machines: RAID and I/O errors are watched even without SMART.

Disk fill and space

  • Fill forecast from daily minima rather than spikes; inodes separately.
  • Where the space went: a tree of the largest directories, journal, Docker images and build cache, oversized logs, forgotten dumps.
  • Safe items are freed with a click, the rest comes with a ready command. Optional auto-cleanup at the threshold.

Architecture

Security model

  • The agent only connects out. It listens on no port, runs no arbitrary commands, works as a separate user in a systemd sandbox. The panel stores a SHA-256 of the token, not the token.
  • Permissions are enforced in the API. An account limited to a group cannot reach another group's object even with a direct request. A script probes the live panel with temporary accounts of each role.
  • No root. Backend as uid 10001, unprivileged nginx frontend, containers with no-new-privileges.
  • Protected sign-in. TOTP, address blocking after failed logins with an allowlist, alert on bogus API requests, audit log. The panel refuses to start with a weak secret.
  • Agent updates are signed with an offline key. Even a compromised panel cannot push its own binary to the nodes.
  • You install the root helpers with your own Ansible or by hand. The panel never distributes them.

Install

One command

On a clean Linux server: installs Docker, starts Caddy with a Let's Encrypt certificate, generates secrets, prints the panel address and the admin password.

$ curl -fsSL https://raw.githubusercontent.com/mihsergeev/Kervax/main/ops/quickstart.sh | sudo sh
No domain required

Without a domain the panel runs on <server-ip>.sslip.io with a Let's Encrypt certificate.

A server

"Add server" gives a command for the node. Metrics appear within seconds.

A site

The address of the monitor. Scheme, certificate, domain and history fill in from the first check.

Own domain, allowlist, behind an existing nginx, upgrades: installation guide.
