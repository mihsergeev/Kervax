Безопасность

Аудит безопасности на каждом сервере

Без отдельного сканера и агента безопасности: те же ноды, та же панель, те же алерты.

порты снаружиалерт на новый порт

Что открыто в интернет

  • Скан снаружи каждой ноды, сверка с тем, что слушает внутри: процесс и контейнер у каждого порта.
  • Белый список учитывается: порт, открытый только своим адресам, открытым не считается.
  • Только Cloudflare: проверяется, что origin не отвечает никому, кроме него.
  • Новый порт в интернете - алерт. Порт, открытый намеренно, отмечается один раз.
  • Порты сервисов LoadBalancer в Kubernetes проверяются так же.

SSH и доступы

  • SSH: вход по паролю и под root, идущий перебор паролей, защита fail2ban или sshguard, версия в баннере.
  • Учетки и ключи: кто может войти, с какими ключами, у кого sudo и NOPASSWD, слабые ключи, учетки, в которые давно не входят.
  • Изменения: новый ключ, пользователь, правило sudo, вход по паролю с нового адреса - алерт с кнопкой "это мы".
  • Хронология за 90 дней: порты, контейнеры, пользователи, sudoers, кроны.

Уязвимости и версии без поддержки

  • Пакеты сверяются с базой OVAL от Canonical: только критичные и уже эксплуатируемые в атаках (CISA KEV).
  • Ядро - по запущенной версии, а не по установленной: видно, кому нужна перезагрузка.
  • Версии без поддержки: ОС, PostgreSQL, MySQL, Redis, nginx, PHP, Node.js, Python и другие, снимок endoflife.date внутри панели.
  • Обновления ОС: невыкаченные обновления безопасности, выключенные автообновления, перезагрузка, которую откладывают.
  • Контейнеры с привилегиями, ключами хоста или сокетом Docker внутри, порты в обход фаервола.

Диски и железо

Поломка видна до того, как случилась

Прогнозы по истории, а не пороги по текущему значению.

SMARTRAIDNVMe

Износ и здоровье дисков

  • Прогноз износа SSD: скорость по замерам, дата 90% и 100% при текущей записи, алерт за 60 дней.
  • Кто пишет на диск: юниты, контейнеры и поды, за час, сутки и неделю.
  • Здоровье: деградировавший RAID, отказ по SMART, растущие переназначенные и нечитаемые сектора, пропавшие диски, ошибки в журнале ядра.
  • Диски виртуальных машин: RAID и ошибки ввода-вывода видны и без SMART.

Prometheus остается инструментом для прикладных метрик и PromQL и работает рядом. Kervax закрывает инфраструктуру: хост, сайт, сертификат, контейнер, базу, бэкап и их безопасность.

Архитектура

Модель безопасности

  • Агент только подключается наружу. Не слушает портов, не выполняет произвольных команд, работает под отдельным пользователем в песочнице systemd. Панель хранит SHA-256 токена, а не токен.
  • Права проверяются в API. Учетка, ограниченная группой, не получит чужой объект даже по прямому запросу. Живую панель проверяет скрипт с временными учетками каждой роли.
  • Без root. Бэкенд под uid 10001, фронт на непривилегированном nginx, контейнеры с no-new-privileges.
  • Вход защищен. TOTP, блокировка адреса после неудачных входов с белым списком, алерт на левые запросы к API, журнал действий. Со слабым секретом панель не запускается.
  • Обновления агента подписаны офлайн-ключом. Даже взломанная панель не выкатит на ноды свой бинарь.
  • Root-helper'ы ставите вы своим Ansible или руками. Панель их не рассылает.

Установка

Одна команда

На чистом Linux-сервере: ставит Docker, поднимает Caddy с сертификатом Let's Encrypt, генерирует секреты, выводит адрес панели и пароль администратора.

$ curl -fsSL https://raw.githubusercontent.com/mihsergeev/Kervax/main/ops/quickstart.sh | sudo sh
Домен не обязателен

Без своего домена панель работает на <IP-сервера>.sslip.io с сертификатом Let's Encrypt.

Сервер

"Добавить сервер" выдает команду для ноды. Метрики появляются через несколько секунд.

Сайт
